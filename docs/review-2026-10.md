# magic-sound-player: documentation review

Comparison of [hww/magic-sound-player](https://github.com/hww/magic-sound-player) (`magic.asm`) with the original `MAG.COM` (`idapro/mag.com`, identical to the copy on the `mag-player` disk) and with the Patisonic source `MagicSound/SRC/mag.txt` (from hww/Aleste520EX).

The code of `magic.asm` matches the original binary. The issues below are in the documentation (README and comments), plus one open question about the hardware.

## Documentation issues

| # | Where | What the documentation says | What the code / binary actually does | Evidence |
|---|---|---|---|---|
| 1 | README ("byte-for-byte identical") | The rebuilt `magic.com` is byte-for-byte identical to the original | Not identical: 3938 bytes vs 4480, and 382 bytes differ in the common part. Almost all differences come from the messages translated from Russian (KOI-8) to English, which shifts the addresses pointing to them. One real change: the module title is copied with 20 bytes instead of 19 | `0CB5h`: original `LD BC,13h`, rebuilt `LD BC,14h`; message pointers e.g. `11BBh` → `0FD5h` |
| 2 | STM pattern format comment (`magic.asm`, lines ~1081-1082) | Byte 1 bits 2..0 = **high** 3 bits of volume; byte 2 bits 7..3 = **low 5** bits of volume, bits 3..0 = command (the two byte-2 fields overlap at bit 3) | Byte 1 bits 2..0 = **low 3** bits of volume; byte 2 bits 7..4 = **high 4** bits of volume, bits 3..0 = command. 7 bits in total (0-64), as in the STM format | `next_note`: volume = `(byte1 AND 7) OR ((byte2 RRCA) AND 78h)` |
| 3 | Channel force-off (pseudo-C comment before the channel code) | `out(DMAMASK, stop); out(pvol, 0x40); // silence` | The DMA mask is **not** written: `LD BC,DMAMASK` is immediately overwritten by `LD BC,VOL_x`, as in `mag.txt` where the `OUT` is commented out. The value written to the volume register is **`0`**, not `40h` | Channel A at `039Dh` (same in B `0456h`, C `050Fh`, D `05C8h`) |
| 4 | Volume write (pseudo-C comment) | `if (v == 0 \|\| v == 1) v = 0x40; out(pvol, v);` | Writes **`(v - 1) * 4`**, with a minimum of 0. The `AND 3Fh` afterwards is only for the VU meter | Channel A at `03F9h`: `SUB 1` / `JR Z` / `JR NC` / `LD A,0` / `SLA A` / `SLA A` / `OUT (C),A` (same in B `04B2h`, C `056Bh`, D `0624h`) |

## Open question: volume register convention (`FAD0h`-`FAD3h`)

| Source | Volume bits | Silence value | Code |
|---|---|---|---|
| `MagicSound/DOC` ("D5-0 is volume") and `mag.txt` | **D5..D0** (0-63) | **`40h`** (bit 6) | `MA_5: LD A,40H` / `MA_4: LD BC,PVOL` / `OUT (C),A` (no shift) |
| Released `MAG.COM` binary | **D7..D2** (`(v-1)*4`) | **`0`** | `LD A,0` / `SLA A` / `SLA A` / `OUT (C),A` |

`mag.txt` seems to be an older version than the released binary, and the board may have changed between them. Which board revision uses which convention? This is needed to emulate the volume correctly in the FPGA core.
